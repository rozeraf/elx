# elx — улучшения фильтрации и UX

План по итогам ревью `cli.rs`, `config.rs`, `fs/walker.rs`, `display/mod.rs`.
Пункты расположены в порядке реализации. Порядок сделан так, чтобы каждый шаг опирался на предыдущие.

---

## 0. Фундамент: переопределения по режимам (`[all]`, `[tree]`)

Разные режимы требуют разного поведения. Например:

- обычный режим: без `/` у директорий, с цветами;
- `-a/--all`: с `/` и без цветов;
- `-T/--tree`: `git_ignore = "dim"` и свёрнутые `target`, `node_modules`.

Сейчас так уже работает одна секция, `[when_not_tty]`: она частично переопределяет базовые ключи.
Предлагаю обобщить этот механизм. Секции `[all]` и `[tree]` содержат те же ключи, что и корень
конфига, но все они необязательные: заданный ключ перекрывает базовое значение, незаданный наследуется.

```toml
classify = false
color = true
git_ignore = "hide"

[all]          # применяется при -a / --all
classify = true
color = false

[tree]         # применяется при -T / --tree
git_ignore = "dim"
collapse = ["target", "node_modules", ".git"]
```

**Порядок применения** (каждый следующий слой перекрывает предыдущий):

```
базовый конфиг → [all] (если -a) → [tree] (если -T) → [when_not_tty] (если не TTY) → флаги CLI
```

- `when_not_tty` идёт после режимов, потому что в пайпе цвета и гиперссылки отключаются всегда, какой бы ни был режим.
- CLI всегда побеждает.
- При `-aT` применяются обе секции, `[tree]` после `[all]`.

**Ключи, которые можно переопределять:** `icons`, `color`, `classify`, `git_ignore`, `ignore`,
`hyperlinks.enabled`, `collapse`, `depth`, `sort.*`.
Начать со скалярных ключей (`icons`, `color`, `classify`, `git_ignore`), остальные добавлять по мере надобности.

**Семантика списков (`ignore`, `collapse`):** значение в секции **заменяет** базовый список, а не
дополняет его. Так поведение предсказуемо, и в режиме можно убрать паттерн. Для дополнения
достаточно продублировать нужное.

**Реализация:** отдельная структура `ModeOverrides`, где у каждого поля тип `Option<T>`, и метод `apply(&mut self)`
на итоговых опциях. `[when_not_tty]` переводится на ту же структуру, чтобы не было двух механизмов.
Вся логика слоёв сосредоточена в `DisplayOptions::new`.

## 1. `git_ignore = "hide" | "dim" | "show"`

Сейчас доступно только «скрыть» (по умолчанию) или «показать как обычные» (`-G`).
Новый режим `dim` показывает игнорируемые файлы приглушённым цветом. Статус `!` уже есть в `git.rs`.

- Обход: при `dim` и `show` вызывается `git_ignore(false)`, а отрисовка красит записи со статусом `!` в тусклый цвет.
- Обратная совместимость: `true` → `hide`, `false` → `show` (serde `untagged` или собственный `Deserialize`).
- CLI: `-G` по-прежнему означает `show`. Опционально `--git-ignore=<mode>`.
- Проверить, что статус `!` действительно выставляется для игнорируемых файлов: `gix` может не отдавать их по умолчанию.

## 2. Сворачивание директорий в дереве: `collapse`

`collapse = ["target", "node_modules", ".git"]` (глобы). Свёрнутая директория выводится одной строкой
`target/ …` (можно с числом элементов внутри), в неё не заходим. Структура видна, шума нет.

- В `Walker::collect_at`: если имя совпадает с паттерном, `children` не собираются, запись помечается как свёрнутая.
- Обычно задаётся в `[tree]` (см. п. 0), но работает в любом рекурсивном режиме.
- CLI: `--collapse <globs>` и `--no-collapse`.

## 3. Сводка скрытого

Внизу вывода (только в TTY):

```
7 hidden (4 gitignored, 3 by pattern) — use -a / -G to show
```

Отвечает на вопрос «а где мой файл?». Для этого нужно, чтобы walker считал отброшенные записи
по причинам; `ignore` сам их не возвращает, придётся считать отдельно. Отключается через
`show_hidden_summary = false`.

## 4. «Показать всё» и отключение ignore из конфига

- Сейчас `ignore` из конфига с CLI отключить нельзя: `DisplayOptions::new` делает только `extend`.
  Добавить `--no-config-ignore`.
- `-aa` (или `-u/--unrestricted`): снимает все фильтры сразу, то есть скрытые, gitignore и паттерны конфига.
  Проверить, что clap `ArgAction::Count` на `-a` не ломает `--all`.

## 5. `--changed`

Показывать только файлы со статусами `M/A/D/?` и директории-предки, в которых они лежат.
Статусы уже собираются в `Walker::collect`, нужен только проход, обрезающий дерево.
С `-T` получается обзор изменений в репозитории.

## 6. `--only` и фильтры по типу

- `--only "*.rs,*.toml"`: показывать только совпадения. В дереве директории, пустые после фильтра, убираются.
- `-D/--dirs-only`, `--files-only`.

## 7. Отмена паттерна через `!` в `--ignore`

`--ignore '!.env.example'` возвращает файл, который скрыт паттерном из конфига. Сейчас `walker.rs`
дописывает `!` ко всем паттернам вслепую, поэтому нужна инверсия: `!x` → `x` (whitelist) и `x` → `!x`.
Внимание: в `OverrideBuilder` любой whitelist-паттерн превращает остальное в «не совпало», семантику надо проверить.

## 8. `.elxignore`

Локальный игнор проекта: `WalkBuilder::add_custom_ignore_filename(".elxignore")`, одна строка.

## UX

- **`--sort` через `clap::ValueEnum`** вместо `String`. Неизвестный ключ даёт ошибку clap со списком значений,
  а не тихий откат на `name`. Значения попадают в автодополнение.
- **Автодополнение shell** (`clap_complete`, новая зависимость, оправдана числом флагов): скрытый `--completions <shell>`.
- **`--print-config`**: итоговый конфиг после всех слоёв, включая `[all]`, `[tree]` и `[when_not_tty]`
  для текущего набора флагов. С п. 0 это главный инструмент отладки.
- **`-L <N>`** как синоним `--depth` (как в `tree`). `--depth` без `-T` включает режим дерева.

## Баг: пример `[hyperlinks]` в README

В README указаны поля `directories`, `underline_files`, `underline_directories`, `underline_symlinks`,
`exclude_env`. В `HyperlinkConfig` вместо них `dirs` и `executables`, underline нет, при этом стоит
`deny_unknown_fields`. Если скопировать пример в конфиг, он не загрузится (вывод по коду, не проверено запуском).
Исправить README или реализовать недостающие поля.

## Не делаем пока

- Именованные профили фильтров (`--filter rust`).
- Фильтры по размеру и дате (`--newer 2d`, `--larger 1M`).
